# IP-0007 — Autonomous bad-zone avoidance/recovery + Select randomization

*Abbreviated package doc (`BL-0012`) — user-authorized pace exception continues from the MVP push.*

| Field | Content |
|---|---|
| **ID / Feature(s)** | IP-0007 / FEAT-1030 (extended: recovery, not just detection) |
| **Traces to** | MSTR-001 C5 (amended v1.1), GDS-01 (loop item 4, new), GDS-03 §5 (amended) |
| **Directive** | Project owner, directly: "If you are already able to detect bad zones, avoid them or navigate naturally out of them. The Select button is only for the user to reset/randomize if they want to." |
| **Scope** | `music_engine.py`: `_emit_channel_gen` now overrides the LFSR-picked delta when `BAD_ZONE_FLAGS` bit0 (DISSONANT) is set — pulls the channel's scale degree toward the tonic (degree 0) instead, so all three pitched channels converge toward the same pitch class and the interval-based dissonance score drops on its own. If bit1 (STUCK) is set and the resulting delta is still 0, a step is forced anyway. At timer-reload, if bit2 (OVERLOAD) is set, the reload value is doubled again (stacking with the wave channel's own existing half-rate doubling), spacing onsets out. `_emit_noise_gen` gets the same overload-driven reload doubling. `init_engine` (both boot and Select) now reseeds each channel's LFSR from the `DIV` register (0xFF04) XORed with a fixed per-channel constant, guarded against a zero seed (a Galois LFSR seeded to 0 never leaves 0) — the "randomize" half of Select's new reset-and-randomize role; the tempo/octave/scale/density/channel-mix indices still reset to the fixed deterministic preset. |
| **Fixed during implementation** | Two `JR` (relative jump) instructions in the per-channel/noise generation routines went out of 8-bit relative-branch range once the recovery logic lengthened those routines — converted to `JP_NZ` (absolute, unlimited range) at the two early-exit guards. |
| **Test evidence** | `test_rom.py` T10 (new): confirms the engine both enters a bad zone and recovers from it autonomously (no Select) over a 4000-frame run. Revised T5.5/T8 assertions that assumed a fixed LFSR seed (no longer true post-randomization) to check *shape* (valid ranges, one-DELTA_TABLE-step-from-reset values, "read on the exact reset frame before a new same-frame onset can regenerate state") rather than exact fixed values — each change documented inline with why. Full regression: **60/60**. An 8000+ frame stress run with input churn confirmed no hangs and observed both bad-zone entry and self-recovery. |
| **G5 gate** | ✅ 32768 bytes, valid header; ✅ 60/60 |
| **Findings** | A genuine, rare (~0.1% of frames), self-healing one-frame transient was found where `BAD_ZONE_FLAGS` bit3 (COMBINED) can read one frame behind bits0-2 — investigated, static code review of `_emit_badzone_tick` shows the combined-bit computation is logically correct and unconditional every call; the transient's exact root cause (likely a PyBoy tick()-boundary/CPU-execution-granularity artifact rather than a logic bug) was not fully chased down given its severity (cosmetic only — affects one frame of the visualizer's palette choice, nothing audible, nothing that affects the recovery mechanism itself, which operates on bits0-2 directly rather than bit3). Flagged to the backlog rather than silently tolerated. |
