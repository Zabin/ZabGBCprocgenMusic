# IP-1070 — Combinable Generation Schemes (Scheme E)

| Field | Content |
|---|---|
| **Package ID** | `IP-1070` |
| **Objective** | Add a second per-pitched-channel note-selection strategy — Scheme E (Euclidean-gated onset timing + fixed-motif pitch selection) — alongside the shipped Scheme W (LFSR-driven walk), selectable per channel via spare bits in the already-shipped `CHMIX_MASKS` table, per `FS-107`/`ADS-100`/`ADR-0001`. |
| **Requirements Covered** | `FR-1180` (scheme-select bit determines strategy), `FR-1190` (scheme switch takes effect at next onset), `FR-1200` (Scheme E onset timing reuses the Euclidean-pattern mechanism), `FR-1210` (Scheme E pitch selection via a fixed motif), `FR-1220` (bad-zone detection/recovery is scheme-agnostic), `NFR-1060` (ROM/WRAM budget), `NFR-1070` (no new WRAM control byte/input control) |
| **Architecture Components** | `ADS-100` (full design), `ADR-0001` (scheme selection rides `CHMIX_IDX`'s preset space), GDS-03 §1 (module ownership — stays in `music_engine.py`, no new module), `FS-107` (System Behaviour, Module Responsibilities) |
| **Interfaces** | Extends `_emit_channel_gen`'s existing note-selection step (`music_engine.py`, currently the LFSR-delta block inside the function starting at line 261) with a scheme-select branch, reusing the existing `CHANNELS`-tuple parameterization pattern (adding a `scheme_bit` field per pitched channel, analogous to `IP-9010`'s `bit_index`) and the existing `_euclidean_pattern`/`DENSITY_K`/`chmix_masks_table` machinery (`IP-0003`/`IP-9010`) rather than inventing new ones. |
| **Files to Create/Modify** | `music_engine.py` only — (1) add a new `MOTIF_TABLE` ROM data block (4 motifs × 8 scale-degree-delta entries, per `ADS-100` §5's sizing estimate); (2) add 3 new WRAM scratch bytes, one per pitched channel (`MOTIF_STEP_PA`/`PB`/`WV`, tracking each channel's current position in its assigned motif when running Scheme E) — placed at `0xC038`-`0xC03A` (confirmed free against `docs/architecture/07-data-model.md`: `0xC020`-`0xC037` is the reserved-but-unused ring-buffer range `BL-0013` already tracks, must not be touched; `0xC038`-`0xC04F` is genuinely unused headroom before `JOY_PREV` at `0xC050`); (3) extend the `CHANNELS` tuple (`pa`/`pb`/`wv` entries) with a `scheme_bit` field (the bit position within `CHMIX_MASKS`'s spare bits 4-6 this channel's scheme-select reads — pa=4, pb=5, wv=6, one bit per channel, per `ADS-100` §2) and a `motif_step` WRAM address field; fix up all existing `CHANNELS`-unpacking call sites (`init_engine`, the two `engine_tick` loops, the final `_emit_channel_gen`/`_emit_arpeggio_tick` emission loop — 4 sites total, same pattern `IP-9010` already established for its own tuple extension) to carry the two new fields through; (4) `_emit_channel_gen`'s note-selection step: before the existing LFSR-delta computation, read `CHMIX_MASKS[CHMIX_IDX]`'s `scheme_bit` for this channel; if set (Scheme E), skip the LFSR-delta path and instead (a) check this channel's Euclidean-pattern position (reusing `_euclidean_pattern`'s already-emitted `noise_pattern_table`, keyed the same way `_emit_noise_gen` already keys it, by `DENSITY_IDX*16 + step`) to decide whether this tick is an onset at all, (b) on a pattern-hit onset, advance `motif_step` (mod 8, wrap) and add `MOTIF_TABLE`'s entry at `[scheme_channel_motif_index*8 + motif_step]` to the *previous* degree (or set directly, per `ADS-100` §5's "cyclic sequence" framing — implementation's choice, document whichever is chosen) to get the new `cur_degree`; if clear (Scheme W), fall through to the existing unmodified LFSR-delta path exactly as today. Note: unlike Scheme W, a Scheme-E channel's onset itself is gated by the Euclidean pattern rather than the note-timer countdown alone — the existing `NOTE_TIMER_*` countdown-to-zero check still governs the *tick rate* at which the pattern is checked (same per-frame call structure), but the actual onset (register write + `cur_degree` update) only fires on a pattern hit, analogous to how the noise channel's own onset is pattern-gated today. (5) `init_engine` (`music_engine.py`, `init_engine` label): zero each pitched channel's new `MOTIF_STEP_*` byte on both boot and Select-reset paths, same pattern every other per-channel field already follows. |
| **Implementation Tasks** | (1) Add `MOTIF_TABLE` (4×8 = 32 bytes, scale-degree deltas — first-guess placeholder content, same "not tuned by ear yet" convention as every other untuned constant, `BL-0005`'s disposition covers this) and its own emission label alongside the other data tables. (2) Add `MOTIF_STEP_PA`/`PB`/`WV` WRAM constants at `0xC038`-`0xC03A`. (3) Extend the `CHANNELS` tuple + fix up all 4 unpacking call sites (verified against the current tree: `init_engine`'s loop, `engine_tick`'s two loops, the final emission loop — same 4 sites `IP-9010` touched for its own extension). (4) Implement the scheme-select branch in `_emit_channel_gen`'s note-selection step, reusing `_euclidean_pattern`'s already-emitted pattern table and `DENSITY_IDX` exactly as `_emit_noise_gen` already keys them — no new pattern-generation code, only a new *consumer* of the existing one. (5) Decide and document which specific bit (4, 5, or 6) each of pa/pb/wv reads from `CHMIX_MASKS` — `ADS-100` §2 names the range but not the exact per-channel assignment; this package's own choice, documented in its Implementation Summary. (6) Zero `MOTIF_STEP_*` in `init_engine`'s boot/Select path. (7) Confirm (by code-reading, not new logic) that `_emit_badzone_tick`'s dissonant-pull-toward-tonic override, which writes `cur_degree` directly, composes correctly with a Scheme-E channel's own motif-index write within the same onset event — the override must win when active, exactly as it already does for Scheme W (per `FR-1220`); if the current write ordering doesn't already guarantee this, resolve it explicitly and document the resolution, don't leave it ambiguous. |
| **Tests to Add** | New `test_rom.py` suite (e.g. `T14`): (a) drive `CHMIX_IDX` to a preset (data value TBD, this package's own choice) that assigns Scheme E to at least pulse A, run long enough to observe multiple onsets, and assert `MOTIF_STEP_PA` cycles through a repeating pattern (e.g. `0,1,2,...,7,0,1,...`) rather than free-running — confirming Scheme E's pitch selection is live; (b) assert pulse A's onset *timing* under Scheme E matches the Euclidean-pattern-gated schedule (comparable to how `T7` already asserts the noise channel's own pattern-gated onset timing) rather than firing every fixed-tempo-reload interval; (c) confirm a channel not assigned Scheme E (still Scheme W) is unaffected — regression guard; (d) drive the engine into a bad zone with a Scheme-E channel active and confirm the existing dissonant/stuck/overload override behavior (`T8`/`T10`'s own assertions, re-driven) still holds; (e) confirm Select resets `MOTIF_STEP_PA`/`PB`/`WV` to 0; (f) full regression — all pre-existing suites (`T1`-`T13`) still green. |
| **Documentation Updates** | `Claude.md` (new "Combinable generation schemes" Known Good Behavior bullet, test count update, a new "Change Scheme E's motif table" dev-guide subsection matching the existing "Change channel-mix presets" precedent), `memory.md` (WRAM quick-reference gains `MOTIF_STEP_PA`/`PB`/`WV`), GDS-07 (the three new WRAM addresses are a real data-model addition — extend GDS-07 §3 in place, same discipline `IP-9010`'s own `CHMIX_IDX` row correction used), `docs/pipeline/backlog.md` (`BL-0020` → `DONE` once verified). |
| **Definition of Done** | A pitched channel assigned Scheme E audibly/measurably cycles through a fixed, repeating motif rather than free-drifting; its onset timing is Euclidean-pattern-gated rather than fixed-interval; a channel switch (via `CHMIX_IDX`) takes effect at the next onset, not mid-note; bad-zone detection/recovery applies identically regardless of scheme; Select resets all new WRAM; every pre-existing test still passes; ROM still builds to 32768 bytes with a valid header. |
| **Verification Checklist** | ROM builds, exactly 32768 bytes, valid header (G5). Full `test_rom.py` suite passes, including the new suite (G5). `09-package-verification` independently drives a non-default, realistic scheme-assignment combination (e.g. Scheme E on wave only, Scheme W on pulse A/B) live and confirms the DoD holds off whatever single fixture the new suite happens to use — per this project's standing tunable-parameter/non-default-combination verification standard (`VR-0002`-`VR-0004`, `VR-9010`, `VR-9020` precedent). |
| **Dependencies** | `IP-0001`-`IP-0003` (`_emit_channel_gen`, `_euclidean_pattern`, `DENSITY_IDX` — all `VERIFIED`). `IP-9010` (`CHMIX_MASKS`, the shipped bit layout this package's scheme-select bits ride — `VERIFIED`, confirmed shipped with bits 0-3 as channel-active exactly as `ADR-0001` assumed). No dependency on `IP-1060`/`IP-1061` — functionally independent, touches adjacent code only (both extend `_emit_channel_gen`/`CHANNELS`, neither reads the other's state). |
| **Risks** | ROM/WRAM budget: `MOTIF_TABLE` (32 bytes) + 3 new WRAM bytes — small, but not yet measured against actual headroom (`NFR-1060`); this package should confirm against the printed `build_rom.py` layout. Audible-contrast risk (carried from `ADS-100`/`FS-107`): whether Scheme E reads as clearly distinct from Scheme W is a `09-content-review` judgment call, not resolvable here — flagged so that review specifically listens for it. Composition risk: the bad-zone dissonant-pull override's interaction with Scheme E's own motif-index write (Implementation Task 7) is this package's single most implementation-risk-bearing decision — get the write ordering right and document it, don't leave it implicit. |
| **Rollback Considerations** | Fully additive (new table, new WRAM, a new branch in an existing function, extended tuple fields) — reverting is a straightforward commit revert; no existing WRAM address reused, no existing behavior (Scheme W) removed or altered. |
