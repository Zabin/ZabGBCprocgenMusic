# IP-1080 — Genre-Aware Style Presets

| Field | Content |
|---|---|
| **Package ID** | `IP-1080` |
| **Objective** | Add a parallel `STYLE_TABLE` keyed by the existing `CHMIX_IDX` preset index and the routine that applies a style row's target `TEMPO_IDX`/`DENSITY_IDX`/`SCALE_IDX`/`DUTY_BIAS` values immediately on a Start press, per `FS-108`/`ADS-101`. |
| **Requirements Covered** | `FR-1230` (`CHMIX_IDX` preset maps to a style row), `FR-1240` (style values applied immediately, not gated to next onset), `FR-1250` (at least 3 audibly-distinct styles), `FR-1260` (preset-0 style matches shipped default, no regression), `NFR-1080` (ROM/WRAM budget), `NFR-1090` (no new input control) |
| **Architecture Components** | `ADS-101` (full design), GDS-03 §1 (module ownership — stays in `music_engine.py`, no new module), `FS-108` (System Behaviour, Module Responsibilities) |
| **Interfaces** | Adds a new routine (`_emit_apply_style`) called from the same site `input_map.py`'s `_step_on_bit` already triggers for `CHMIX_IDX` (`input_map.py:61`) — an added step in that existing call chain, not a new call site or a change to `_step_on_bit`'s own code. Reads the existing `TEMPO_IDX`/`DENSITY_IDX`/`SCALE_IDX` WRAM addresses (`music_engine.py`) and writes them via the same plain `LD_nn_A` pattern `input_map.py`'s D-pad/A/B handlers already use — no new write mechanism invented. |
| **Files to Create/Modify** | `music_engine.py` only — (1) add a new `DUTY_BIAS` WRAM constant at `0xC03B` (confirmed free against `docs/architecture/07-data-model.md`: `0xC038`-`0xC03A` is `IP-1070`'s `MOTIF_STEP_PA`/`PB`/`WV`, `0xC03B`-`0xC04F` is genuinely unused headroom before `JOY_PREV` at `0xC050`); (2) add a new `STYLE_TABLE` ROM data block — 8 rows × 4 bytes (`tempo_idx`, `density_idx`, `scale_idx`, `duty_bias`), values per this package's TWBS entry (index 0 = default: `PRESET_TEMPO_IDX`/`PRESET_SCALE_IDX`/`PRESET_DENSITY_IDX`/0; index 1 = Techno/Chiptune-Driving: high tempo, high density, minor or dorian scale index, positive duty bias; index 2 = Ambient/Lo-Fi: low tempo, low density, major or pentatonic scale index, negative or zero duty bias; index 3 = Holiday: mid tempo, mid-steady density, major scale index, positive duty bias; indices 4-7 = copy of index 0's row) — exact numeric BPM-table/scale-table indices are this package's own tuning choice within the qualitative targets `ADS-101`/`FS-108` name, same "data, not shape" deferral as every prior preset table; (3) implement `_emit_apply_style(rom)`: read `CHMIX_IDX`, compute `style_table + CHMIX_IDX*4` via the existing `_ld_hl_label`/`ADD_HL_BC` idiom every other indexed-table read in this file already uses, then read and store the 4 bytes into `TEMPO_IDX`/`DENSITY_IDX`/`SCALE_IDX`/`DUTY_BIAS` in turn; (4) call `_emit_apply_style(rom)` from `input_map.py`'s Start-press handling site immediately after `_step_on_bit`'s existing `CHMIX_IDX` step (same frame, same call chain — confirmed by reading `input_map.py:61`'s surrounding context, no other logic sits between the step and where this call is added); (5) `_emit_channel_gen`'s duty-cycle write site (`music_engine.py:540-547`): change the index computation from `cur_degree & 0x03` alone to `(cur_degree + DUTY_BIAS) & 0x03` (reusing the existing `AND 0x03` masking idiom, wrap not clamp, per this package's own combination-rule decision); (6) `init_engine`: zero `DUTY_BIAS` on both boot and Select-reset paths (index-0/default value, per `FR-1260`), same pattern every other per-preset field already follows. |
| **Implementation Tasks** | (1) Add `DUTY_BIAS` WRAM constant at `0xC03B`. (2) Add `STYLE_TABLE` (32 bytes) with the 4 defined style rows (index 0 default, 1 Techno, 2 Ambient/Lo-Fi, 3 Holiday, 4-7 copies of 0) and its own emission label alongside the other data tables. (3) Implement `_emit_apply_style`, reusing the existing indexed-table-read idiom (`_ld_hl_label` + `ADD_HL_BC` + `LD_A_HL`) already used for every other `CHMIX_IDX`-style lookup (`chmix_masks_table`) — read 4 consecutive bytes (auto-advancing `HL` after each `LD_A_HL`) rather than 4 separate index computations. (4) Wire the call into `input_map.py`'s existing Start-press handling, verified against the current tree to confirm no other logic sits between `_step_on_bit`'s `CHMIX_IDX` step and this new call. (5) Change the duty-cycle write site's index computation to include `DUTY_BIAS`, wrap via `AND 0x03`. (6) Zero `DUTY_BIAS` in `init_engine`'s boot/Select path. (7) Confirm (by code-reading, not new logic) that `_emit_apply_style`'s writes to `TEMPO_IDX`/`DENSITY_IDX`/`SCALE_IDX` don't need to interact with any in-flight bad-zone override — `_emit_badzone_tick`/`IP-0007`'s overrides read/write `CUR_DEGREE_*` and `BAD_ZONE_FLAGS`, never `TEMPO_IDX`/`DENSITY_IDX`/`SCALE_IDX` directly, so no ordering conflict is possible by construction; document this confirmation rather than leaving it assumed. |
| **Tests to Add** | New `test_rom.py` suite (e.g. `T15`): (a) drive `CHMIX_IDX` to index 1 (Techno) via Start presses and assert `TEMPO_IDX`/`DENSITY_IDX`/`SCALE_IDX`/`DUTY_BIAS` all read that row's documented values on the exact same frame as the press (verifying `FR-1240`'s "immediate," not "next onset," timing — read on the press frame itself, not after a settling delay, distinguishing this from `IP-1070`'s own next-onset-gated `T14` assertions); (b) repeat for index 2 (Ambient/Lo-Fi) and index 3 (Holiday), confirming each produces its own distinct combination; (c) drive `CHMIX_IDX` back to index 0 and assert the combination exactly matches the pre-`IP-1080` shipped default (`PRESET_TEMPO_IDX`/`PRESET_SCALE_IDX`/`PRESET_DENSITY_IDX`, `DUTY_BIAS`=0) — regression guard for `FR-1260`; (d) drive the engine into a bad-zone state, then trigger a style change, and confirm `DISSONANCE_SCORE`/`BAD_ZONE_FLAGS`/`STALE_COUNT_*`/`ONSET_WINDOW_COUNT` are unchanged by the style-change frame itself (only `TEMPO_IDX`/`DENSITY_IDX`/`SCALE_IDX`/`DUTY_BIAS` differ) — confirms the style/bad-zone independence `FS-108`'s acceptance criterion (4) requires; (e) confirm Select resets `DUTY_BIAS` to 0 alongside every other per-preset field it already resets; (f) full regression — all pre-existing suites (`T1`-`T14`) still green. |
| **Documentation Updates** | `Claude.md` (new "Genre-aware style presets" Known Good Behavior bullet, test count update, a new "Change style-preset values" dev-guide subsection matching the existing "Change channel-mix presets"/"Change Scheme E's motif table" precedents), `memory.md` (WRAM quick-reference gains `DUTY_BIAS`), GDS-07 (the new WRAM address and `STYLE_TABLE`'s ROM section are a real data-model addition — extend GDS-07 §3 in place, same discipline every prior package's WRAM addition used), `docs/pipeline/backlog.md` (no direct backlog item to close — R5 rides the roadmap, not a single `BL-xxxx`; `BL-0038` closes once the `DUTY_BIAS` combination rule this package implements is confirmed working by test). |
| **Definition of Done** | Selecting any of the 3 named-style `CHMIX_IDX` presets immediately (same frame) sets `TEMPO_IDX`/`DENSITY_IDX`/`SCALE_IDX`/`DUTY_BIAS` to that style's documented values; preset 0 remains identical to the pre-`IP-1080` shipped default; a style change leaves all bad-zone WRAM state untouched; Select resets `DUTY_BIAS` to 0; every pre-existing test still passes; ROM still builds to 32768 bytes with a valid header. |
| **Verification Checklist** | ROM builds, exactly 32768 bytes, valid header (G5). Full `test_rom.py` suite passes, including the new suite (G5). `09-package-verification` independently drives a non-default style selection (e.g. index 3, Holiday) live and confirms the DoD holds off whatever single fixture the new suite happens to use, per this project's standing tunable-parameter/non-default-combination verification standard (`VR-1070`'s own precedent — drive a combination the suite's own fixture never varies). |
| **Dependencies** | `IP-0001`-`IP-0003` (`TEMPO_IDX`/`DENSITY_IDX`/`SCALE_IDX`, all `VERIFIED`). `IP-0001` (`CHMIX_IDX`'s existing Start-stepped read/write path via `input_map.py`'s `_step_on_bit`, `VERIFIED`). `IP-1060` (`DUTY_BY_DEGREE`'s existing duty-cycle write site this package's `DUTY_BIAS` composes with, `VERIFIED`). No dependency on `IP-1070` (Scheme E) — `STYLE_TABLE` is read independently of `CHMIX_MASKS`, confirmed by `ADS-101` §2's "two tables stay independent" design and this package's own supersession-sweep finding. |
| **Risks** | ROM/WRAM budget: `STYLE_TABLE` (32 bytes) + 1 new WRAM byte — small, but this package should confirm against the actual printed `build_rom.py` layout / `rom.pos`-instrumentation measurement (`ADR-0002`'s own method), not merely assumed negligible. Overwrite-reads-as-interference risk (carried from `ADS-101`/`FS-108`): a `09-content-review` judgment call, not resolvable here — flagged so review specifically listens for it. Genre-fidelity risk (carried from `ADS-101`/`FS-108`/`R219`): whether each style reads as *recognizably* its named genre, not just "a different combination," is a `09-content-review` judgment call. Data-tuning risk: the exact BPM/scale-index values chosen for each style (Implementation Task 2) are this package's own first-guess placeholders, same "not tuned by ear yet" disposition as every other untuned constant (`BL-0005`). |
| **Rollback Considerations** | Fully additive (new table, new WRAM byte, a new routine, one new call site, one changed index computation at the duty-write site) — reverting is a straightforward commit revert; no existing WRAM address reused, no existing behavior removed. The one modified pre-existing line (the duty-cycle index computation) reduces to today's exact behavior when `DUTY_BIAS`=0 (which it always is until a style changes it), so even a partial rollback leaves default-preset behavior unchanged. |
