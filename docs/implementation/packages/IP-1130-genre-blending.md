# IP-1130 — Genre Blending

| Field | Content |
|---|---|
| **Package ID** | `IP-1130` · mirrors `FS-113` · **Executor: `08-code-implementation`** · roadmap R8, `FEAT-1130` |
| **Objective** | Interpolate `TEMPO_IDX`/`DENSITY_IDX`/`DUTY_BIAS` between the current and newly-selected `STYLE_TABLE` row over 4 discrete steps on a Start press, instead of the current instant same-frame overwrite; `SCALE_IDX` keeps its existing immediate-apply behavior (categorical, cannot interpolate). No new input control — reuses the existing Start-press `CHMIX_IDX` step. A second Start press mid-blend restarts the blend from the engine's then-current values. |
| **Requirements Covered** | `FR-1470`, `FR-1480`, `FR-1490`, `NFR-1210`, `NFR-1220`, `NFR-1230`. **Amends `FR-1240`** (does not freshly implement it) — supersedes its `TEMPO_IDX`/`DENSITY_IDX`/`DUTY_BIAS` instant-apply guarantee; `SCALE_IDX`'s half is unchanged. |
| **Architecture Components** | [`ADS-107`](../../architecture/ADS-107-genre-blending.md) (the design synthesis and Decision Log — authoritative for the independent-WRAM decision, the `SCALE_IDX` hard-switch, and the compile-time-shift interpolation); [`FS-113`](../../features/fs-113-genre-blending.md) (the behavior contract, the mid-blend-restart contract stated precisely, and the confirmation that `CHMIX_IDX` never lands on its own pre-press value); [`GDS-09` §5](../../architecture/09-interface-specification.md) (per-frame call-order contract — `_emit_blend_tick`'s placement in `engine_tick`); [`GDS-07` §6](../../architecture/07-data-model.md) (WRAM headroom — next free address `0xC070`, re-confirmed at planning time, unaffected by `IP-1120`'s `0xC068`-`0xC069` addition). |
| **Interfaces** | New routines in `music_engine.py`: `_emit_begin_blend(rom)` (replaces `_emit_apply_style` as the routine `input_map.py`'s Start handler calls) and `_emit_blend_tick(rom)` (new call from `engine_tick`, alongside the existing `rom.CALL('song_tick')`). `_emit_apply_style` itself is retired — no other call site references it (confirmed by the supersession sweep, `00-master-build-plan.md`'s own TWBS section for this package). No change to `build_engine_asm`'s or `build_input_asm`'s own signatures. `visuals.py` is untouched. |
| **Files to Create/Modify** | **`music_engine.py`**: (1) add 4 new WRAM constants — `BLEND_SRC_TEMPO = 0xC070`, `BLEND_SRC_DENSITY = 0xC071`, `BLEND_SRC_DUTY = 0xC072`, `BLEND_STEP = 0xC073` — re-confirm `0xC070` unclaimed by grep before writing (last measured free at planning time; the tree may have moved by execution time, same standing discipline every package follows); (2) replace `_emit_apply_style(rom)` (currently `music_engine.py:391-405`) with `_emit_begin_blend(rom)`: unconditionally, on every call — reads `TEMPO_IDX`/`DENSITY_IDX`/`DUTY_BIAS`'s *current* values into `BLEND_SRC_TEMPO`/`DENSITY`/`DUTY` (this is what makes the mid-blend-restart contract, `FR-1490`, correct without any special-casing — the capture always reads whatever the engine currently holds, whether that's a settled value or a value `BLEND_STEP` frames into an earlier blend), then reads `STYLE_TABLE[CHMIX_IDX]`'s row (same `_ld_hl_label`/`ADD_HL_BC` idiom the retired routine already used) and writes only `scale_idx` to `SCALE_IDX` immediately; sets `BLEND_STEP ← 0`; (3) add `_emit_blend_tick(rom)`: if `BLEND_STEP >= 4`, `RET` immediately; else increment `BLEND_STEP`, then for each of `tempo_idx`/`density_idx`/`duty_bias`: read `STYLE_TABLE[CHMIX_IDX]`'s target byte, compute `BLEND_SRC_* + ((target − BLEND_SRC_*) × BLEND_STEP) >> 2`, write to the corresponding WRAM field; (4) call `_emit_blend_tick(rom)` from `engine_tick` (`music_engine.py:1255`, alongside the existing `rom.CALL('song_tick')` — order relative to `song_tick`/`badzone_tick` is not load-bearing per `FS-113`'s own Interfaces Used field, confirmed no shared-write ordering dependency exists this pass; place after `song_tick` for a stable, arbitrary-but-consistent convention). **`input_map.py`**: change the Start handler (`input_map.py:64-74`) to call `_emit_begin_blend(rom)` in place of `_emit_apply_style(rom)` — the `CHMIX_IDX` step itself (`INC_A`/`AND 0x07`) is unchanged; import `_emit_begin_blend` from `music_engine.py` instead of `_emit_apply_style`. **`test_rom.py`**: add the `T21` suite (below); update `T15.1`-`T15.4` (currently asserting same-frame landing of all 4 `STYLE_TABLE` fields) to the new blend contract — `SCALE_IDX` still lands same-frame, `TEMPO_IDX`/`DENSITY_IDX`/`DUTY_BIAS` land after the blend completes (drive to `BLEND_STEP=4` before asserting, or assert `BLEND_SRC_*` on the change frame itself and the final values after N frames, whichever reads more clearly against the existing test's own structure). |
| **Implementation Tasks** | (1) Re-confirm `0xC070`-`0xC073` unclaimed by grep. (2) Add the 4 WRAM constants. (3) Write `_emit_begin_blend`, replacing `_emit_apply_style` in place (same file location, same STYLE_TABLE-read idiom, different write targets). (4) Write `_emit_blend_tick`: propose **`N = 16` frames to completion** (4 steps × 4 frames/step) as the first-guess blend duration (`BL-0005`-class deferral, not tuned by ear — a quarter-second-scale glide at 60fps, chosen as a plausible starting point for "audible drift, not sluggish," explicitly not a content-review-informed value); implement as a per-step frame-countdown or a direct `BLEND_STEP` per-4-frames scheme, implementer's choice, as long as `BLEND_STEP` reaches exactly 4 at frame 16 and the interpolated values at each intermediate `BLEND_STEP` match the formula exactly (no rounding drift). (5) Wire `_emit_blend_tick` into `engine_tick`. (6) Change `input_map.py`'s Start handler's call site and import. (7) Update `T15.1`-`T15.4` to the new contract (this is Implementation Task, not a follow-up — `BL-0099`). (8) Add `T21` per Tests to Add. (9) Rebuild, run the full suite. |
| **Tests to Add** | New `test_rom.py` suite **`T21` — Genre Blending**: (a) on a Start press, assert `SCALE_IDX` matches `STYLE_TABLE[CHMIX_IDX].scale_idx` on the exact press frame, and `BLEND_SRC_TEMPO`/`DENSITY`/`DUTY` match the pre-press `TEMPO_IDX`/`DENSITY_IDX`/`DUTY_BIAS` values (`FR-1470`). (b) drive `N` frames past a Start press (using the package's own implemented `N`, read from the build rather than hardcoded in the test as a magic number, if practical — or documented as matching the implementation's own constant) and assert `BLEND_STEP == 4` and `TEMPO_IDX`/`DENSITY_IDX`/`DUTY_BIAS` exactly equal `STYLE_TABLE[CHMIX_IDX]`'s values, across at least 2 non-default style-pair transitions (`FR-1480`). (c) **forced mid-blend-restart collision**: drive to a Start press, advance to a frame where `1 <= BLEND_STEP <= 3` (empirically derive the exact frame the same way `T17.6`/`T19` already do), press Start again, and assert `BLEND_SRC_*` now equal the `TEMPO_IDX`/`DENSITY_IDX`/`DUTY_BIAS` values in effect on that exact frame (not the original pre-first-press values), `SCALE_IDX` matches the *second* press's target, and `BLEND_STEP` reads 0 immediately after the second press (`FR-1490`). (d) `CHMIX_IDX=0` (default preset) full-blend-cycle regression: after cycling all the way back to preset 0 (mirroring `T15.4`'s own existing method) and letting the blend complete, assert the resulting state matches the shipped default exactly — no regression (`FR-1240`'s surviving `SCALE_IDX` guarantee + the blend's own exact-landing guarantee together reproduce the old instant-apply outcome once settled). (e) full regression — `T1`-`T20` still green, with `T15.1`-`T15.4` updated to the new contract (not merely left passing by accident). |
