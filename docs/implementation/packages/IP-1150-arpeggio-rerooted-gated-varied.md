# IP-1150 — The Arpeggio Re-rooted, Gated and Varied

| Field | Content |
|---|---|
| **Package ID** | `IP-1150` · mirrors [`FS-115`](../../features/fs-115-arpeggio-rerooted-gated-varied.md) · **Executor: `08-code-implementation`** · `FEAT-1160`, `BL-0127` remediation (riding `BL-0125`, `BL-0128`, `BL-0130`) |
| **Objective** | Make the arpeggio **spell the chord the engine is already playing, only when the note it decorates is a chord tone, with a figure drawn per note rather than compiled in — and make it cost *less* per frame than it does today.** `IP-1060` built the arpeggio in 2026-07 to *fake* harmony in its absence (`R216`); `IP-1140` supplied real harmony and nothing revisited it, so `_emit_arpeggio_tick` still adds `[0,2,4,2]` scale-degree offsets, masked `AND 0x07`, **to the chord tone the harmony just chose** — every frame, both pulse channels, forever. Measured on `3e635ed`: pulse B is placed on a current-chord tone at **100 %** of its onsets and only **46.4 %** of sounding pulse-channel frames are chord tones; strong-beat harsh intervals read **12.0 % on intent and 25.7 % on sounding pitch**. The project owner heard the other half of it before any document noticed: **"constant repeated arpeggios."** |
| **Requirements Covered** | `FR-1130` (as amended 2026-08-21), `FR-1600`, `FR-1610`, `FR-1620`, `FR-1630`, `NFR-1280`. Satisfied-but-not-implemented: `NFR-1260`, `NFR-1270` (as amended — **sounding-pitch basis**). **`FR-1140` and `FR-1150` are NOT covered and must NOT be claimed — they must be *preserved*.** They are shipped, `VERIFIED` behaviours produced *by the routine this package rewrites*; see Risk R1 and Task 8. |
| **Architecture Components** | [`ADS-108` §12](../../architecture/ADS-108-harmonic-coordination.md) (D14 — **read §12.4's four rules and §12.5's rejected alternatives before writing anything**). [`ADR-0005`](../../architecture/adr/ADR-0005-the-arpeggio-becomes-chord-aware-gated-and-varied.md) (binding). [`ADR-0004`](../../architecture/adr/ADR-0004-harmonic-coordination-replaces-the-default-walk-in-place.md) and [`ADR-0001`](../../architecture/adr/ADR-0001-scheme-selection-rides-chmix-preset-space.md) (both **unchanged** — no scheme bit, no `CHMIX_MASKS` field, no note-*selection* rule is touched by this package). [`FS-115`](../../features/fs-115-arpeggio-rerooted-gated-varied.md) (authoritative for behaviour). `GDS-07` §3 (WRAM map; next free address `0xC07A`). `R101` §8.5 / `GDS-06` §2.2a (the budget this package must *return* to, not merely respect). |
| **Interfaces** | **No new routine, and `engine_tick`'s call list is unchanged.** `_emit_arpeggio_tick` keeps its signature shape, its label (`arp_tick_{suffix}`), its call site, and — critically — **its position before `gen_tick` in `engine_tick`'s call order**, which is what produces `FR-1150`'s portamento (`Claude.md` states this explicitly; do not reorder). The new per-onset resolution work extends `_emit_channel_gen`'s existing per-channel onset branch, after the note-selection block has settled `CUR_DEGREE` — the same "inside a branch that already exists" discipline `IP-1140` held to. It reuses `_emit_chord_tone_lookup` (`music_engine.py` L443) verbatim for chord-slot → degree resolution. `build_rom.py`'s existing table-emission path carries the new data table; no patch-point key is added or changed. |
| **Files to Create/Modify** | **`music_data.py`** — replace `ARPEGGIO_OFFSETS` (L145) with an arpeggio **pattern table** (`N` rows × 4 entries; entries `0`-`2` are chord-tone slots, one reserved value is `SUSTAIN`) plus its LFSR-indexed 4-entry selector table, shaped exactly like `DELTA_TABLE`/`MOTIF_VARIANT_SELECTOR`/`CHORD_TRANSITION`. **`music_engine.py`** — (1) new per-channel WRAM constants for the onset-resolved arpeggio cache, each re-confirmed unclaimed by `grep` before writing (standing discipline; `GDS-07` records `0xC07A` as next free); (2) a per-onset resolve step inside `_emit_channel_gen`'s onset branch, for `pa`/`pb` only (the `arp_state`-bearing channels — the `CHANNELS` entry already distinguishes them by a non-`None` `arp_state` field, so gate on that, not on a hardcoded suffix); (3) `_emit_arpeggio_tick` (L1024) rewritten to *play back* the cache — deleting its `arpeggio_offsets_table` lookup, its `CUR_DEGREE`+offset arithmetic, its `AND 0x07` mask, **and its whole `SCALE_IDX`/`OCTAVE_IDX`→`ptr_table` address resolution**, which is where the per-frame saving comes from; (4) emit the two new tables with labels alongside the existing `chord_table`/`melody_pick`/`slot_next` emissions (~L1590), removing `arpeggio_offsets_table`; (5) `init_engine` (~L1457) populates the cache for both pulse channels on **both** boot and Select (`FR-1630`). **`test_rom.py`** — new `T23` suite; `T11` re-authored (its `T11.1` asserts the *old* step-cycling contract); `T19` gains an arpeggio-onset frame class. **Untouched, confirm by diff at close: `visuals.py`, `input_map.py`, `patterns.py`, `tiles.py`, `gbc_lib.py`, `build_rom.py`, `wram_constants.py`.** |
| **Implementation Tasks** | **(1)** `grep`-confirm the new WRAM addresses are unclaimed; update `GDS-07`'s next-free line. **(2)** Author the pattern + selector tables in `music_data.py`. Constraints from `FR-1610`, not preferences: at least one row is **all-`SUSTAIN`** (that row *is* the gate, and an all-`SUSTAIN` *table* is `ADR-0005`'s named retirement fallback), and the rows must differ in **how many of the four steps sound a pitch other than the onset pitch** — not merely in the order of slots. Four permutations of one triad sweep do not satisfy this. Values are first-guess placeholders (`BL-0005` class), the *shape* is the commitment. **(3)** Add the WRAM constants and emit the tables. **(4)** Implement the per-onset resolve in `_emit_channel_gen`'s onset branch: read the drawn pattern row (or force the all-`SUSTAIN` row when this note is not a chord tone — for pulse A that is `CHORD_TOGGLE` bit1's weak parity, already read at that onset; pulse B always takes a chord tone so its gate never fires), then resolve the row into the cache. **Draw from the channel's own LFSR** — no new randomness source, same idiom as `_emit_chord_pick`. **(5) Resolve into frequency pairs, not degrees** — the primary shape: for each of the 4 steps, resolve `SUSTAIN` → this note's own pitch, or slot → `_emit_chord_tone_lookup` → note-table entry, and store the `(lo, hi)` pair. `arp_tick` then becomes index-and-write with **no table arithmetic at all**. **Plan B, if and only if Task 9's measurement shows the onset frame itself regressing** (pulse A and pulse B are phase-locked onto the same frame — `BL-0121` — so their onset costs add): cache the 4 resolved **degrees** plus the note-table base pointer instead, moving the per-step note-table read back to `arp_tick` while still deleting the `ptr_table` resolution. Both shapes satisfy `NFR-1280`; the choice is a measurement, not a preference, and whichever ships must be recorded with its numbers. **(6)** Delete the now-dead `ARPEGGIO_OFFSETS` path end-to-end — table, label, emission, and the `ARP_DEGREE_SCRATCH` stash if it becomes unused (`grep` it; it is shared, so confirm before removing). **(7)** `init_engine` populates the cache on both paths (`FR-1630`). **(8) Preserve vibrato and portamento, deliberately and with a test — this is the package's highest-risk task, not a footnote.** `SUSTAIN` means *write this note's own pitch this frame*, **never** *skip the frame's write*. `arp_tick`'s vibrato block and its unconditional final `LDH` writes stay exactly as they are; only the *source of the base pitch* changes. Do not reorder `engine_tick`. **(9) Measure, and report whatever it says**: `VIS_ENTRY_LY` on every `T19` frame class **plus an arpeggio-onset frame**; an emitted-instruction count of `arp_tick`'s common path before vs after (`VIS_ENTRY_LY` proves *within budget*, not *cheaper* — `NFR-1280` requires cheaper); and the `NFR-1270` strong-beat-partitioned harsh-interval measurement **on sounding pitch**, before and after, against `3e635ed`. **(10)** Re-author `T11` and add `T23`; write `T19`'s new frame class. **(11)** Documentation updates below. |
| **Tests to Add** | **New `test_rom.py` suite `T23` — Chord-Aware Arpeggio.** (a) Over a long run at boot defaults, every pitch a pulse channel sounds while arpeggiating is a tone of the chord `CHORD_IDX` names at that instant — reconstructed from WRAM read at the same instant, **never from `SEMI_*`** (`BL-0124`). (b) On weak pulse-A onsets, the sounding pitch is constant for the note's duration apart from vibrato (`FR-1600`). (c) More than one distinct figure is observed per pulse channel, and at least one note per channel does not arpeggiate at all (`FR-1610`). (d) The two pulse channels are observed articulating differently at the same time. (e) **`FR-1140` vibrato and `FR-1150` portamento remain observable on a *sustained, non-arpeggiating* note** — `FS-115` A5, `BL-0130`. **This check does not exist today and is the reason R1 is currently invisible**; author it as a real assertion, not a comment. (f) A scale/octave change during a sounding note lands at the next onset, not mid-note (`FR-1620`). (g) The cache holds defined values after boot **and** after Select, and no pre-reset pitch material sounds (`FR-1630`). **`T19`** gains an arpeggio-onset frame class (`NFR-1260`). **Re-authored, not added: `T11.1`** asserts "the arpeggio step index cycles through more than one value," which describes the *retired* unconditional design — re-derive it against the new contract (a sustaining note's step index legitimately does not change what sounds). `T11.3`/`T11.5` (Select-reset state) must be re-checked against the new init path. **A check weakened until it stops failing is not a passing check** — `IP-1140`'s record shows a loosened `T5.5` would have let a real off-by-one ship. |
| **Documentation Updates** | `GDS-07` — new WRAM rows, updated §6 next-free address and headroom, and the new ROM tables (with `arpeggio_offsets_table` removed). `Claude.md` — the WRAM quick-reference; the test count; the "Sound design techniques" section's **Arpeggio** bullet, which currently describes the retired design verbatim; a "How to Change Things" entry for the pattern table; a Known Good Behavior entry stating plainly that **the boot sound changed again** and why. **`Claude.md`'s `IP-1140` Known Good Behavior entry additionally carries the `BL-0128` figure correction** (its recorded 12.2 %/30.6 %/21.5 % were measured on intent; on sounding pitch the same build reads 25.7 %/36.1 %/30.9 %) — an incorrect headline number left standing is worse than no number. `docs/features/INDEX.md`, `packages/INDEX.md`, `00-master-build-plan.md` status rows. `docs/roadmap/04-release-roadmap.md` — no release row is claimed (this is remediation); flag rather than edit if a row drifts. |

The sounding-pitch before/after `NFR-1270` measurement is **captured and reported in this package's evidence, whatever it says.** `FR-1140`/`FR-1150` are not claimed in traceability — they are preserved and tested. |
| **Verification Checklist** | `09-package-verification` independently: rebuilds and re-runs the full suite; **re-derives at least one note's full articulation by hand** from the drawn pattern row and `CHORD_TABLE`, rather than trusting `T23`(a); confirms on a live drive at a **non-default** `SCALE_IDX` *and* `OCTAVE_IDX` that arpeggiated pitches follow the scale (the chord table is per-scale, and a transcription error in one of four blocks is invisible at the default); **independently confirms that vibrato and portamento survive on a sustained note** — the `BL-0130` check, and the one most likely to have been satisfied by a comment rather than an assertion; re-measures `VIS_ENTRY_LY` on its own drive, including an onset frame where pulse A and pulse B fire together; independently re-counts `arp_tick`'s emitted instructions before/after; and **independently re-runs the strong-beat-partitioned interval measurement on sounding pitch rather than accepting the implementing session's number** — `BL-0128` exists precisely because the wrong basis was banked once already. `09-content-review` separately applies `R224` §7's holistic dimension, with the question stated as **"does the arpeggio still read as a constant looping figure?"** — not "is it in tune." |
| **Dependencies** | `FEAT-1150`/`IP-1140` — **`COMPLETE`, not `VERIFIED`.** Its `CHORD_TABLE`, `CHORD_IDX` and `CHORD_TOGGLE` are exactly what this package reads, and `_emit_chord_tone_lookup` is reused verbatim. **This package is therefore `BLOCKED` by the letter of this plan's `READY` rule** (dependencies must be `VERIFIED`, not merely `COMPLETE`) — recorded honestly rather than papered over; see the Master Build Plan row for the disposition. `FEAT-1060`/`IP-1060`+`IP-1061` (`VERIFIED`, shipped) — this package rewrites their routine and must preserve two of its four effects. `IP-9010`'s mute contract and `IP-0007`'s bad-zone paths are consumed unchanged. No dependency on R8 or R9 in either direction. |
| **Risks** | **(1) `BL-0130`, High — implementing the gate as "skip the per-frame write" silently deletes portamento and vibrato.** `FR-1150`'s glide is produced *by this routine's own* per-frame rewrite carrying the pitch from the outgoing note to the new one (hence its position before `gen_tick`); `FR-1140`'s vibrato rides the same write. The obvious implementation of "a non-chord tone does not arpeggiate" removes both **on every weak melody onset — where portamento matters most — with the entire suite still green**, because nothing today asserts a glide occurred. Mitigated by Task 8's explicit instruction and `T23`(e)'s new assertion, and named again in the Verification Checklist because one sentence in a package is thin protection against the obvious implementation. **(2) High — the VBlank budget, in a new place.** `IP-9040` died here and `IP-1140` survived it. The per-*frame* path gets cheaper by construction, which is the easy half; the risk moves to the **onset frame**, because pulse A and pulse B are phase-locked (`BL-0121`) and their new resolve work lands on the same frame. Task 5's Plan B exists for exactly this and is a measured fallback, not an escape hatch. **(3) Medium — the boot sound changes again**, so "did tests break" no longer separates a regression from the intended change. The sounding-pitch before/after and the listening pass are the acceptance instruments; the suite is a gate, not evidence. **(4) Medium — the fix may not answer the complaint.** "Does it still read as a constant looping figure" is not measurable, and a green suite has never predicted it (`BL-0097`/`BL-0120`). `ADR-0005`'s bounded fallback (an all-`SUSTAIN` table *is* retirement, a data edit) is what keeps this from absorbing unbounded iteration. **(5) Low-Medium — this package writes both `music_engine.py` and `music_data.py`, crossing the stage-08 code/content peer seam (`G1`)**, exactly as `IP-1140` did and declared. Same justification: the table is meaningless without the mechanism and the mechanism untestable without the table, so splitting yields two packages neither independently verifiable. `08-code-implementation` executes both, with `music_data.py`'s edit confined to the arpeggio tables. **(6) Low — ROM budget.** Net expected to be roughly neutral or negative (a small pattern table replaces a 4-byte offset table; `arp_tick`'s deleted address arithmetic removes code bytes from both channels' copies). Report the measured delta; `R104` §7's headroom is ample either way and no bank-switching question arises (`ADR-0002`). |
| **Rollback Considerations** | **Not purely additive — a revert is not a no-op**, the same posture `IP-1140` recorded. Reverting restores the chord-fighting invariant arpeggio as the boot behaviour and would need `FS-115`, `FEAT-1160`, the requirements delta and the re-authored tests reverted alongside, or the baseline and the code disagree. Mechanically it is clean: the change is confined to *articulation between onsets* — note selection, timers, bad-zone bookkeeping, the mute gate, `CUR_DEGREE`'s meaning and every downstream consumer are untouched — so a single-commit `git revert` suffices, with no data migration and no persisted state. **There is also a cheaper partial rollback that a full revert should not be confused with**: setting every pattern row to all-`SUSTAIN` retires the arpeggio outright (`ADR-0005`'s named fallback) while keeping the chord-awareness, the budget recovery and the tests — a one-table data edit. `3e635ed` must remain buildable throughout this package's life, since it is the `NFR-1270` measurement baseline. |
