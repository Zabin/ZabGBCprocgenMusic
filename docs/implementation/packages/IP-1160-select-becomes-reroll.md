| **Objective** | **Make Select a reroll: new melodic material, kept settings.** A Select rising edge shall continue to reseed every pitched channel's LFSR and clear `BAD_ZONE_FLAGS`/`DISSONANCE_SCORE`/`STALE_COUNT_*`/`ONSET_WINDOW_COUNT`, and shall stop changing `TEMPO_IDX`/`OCTAVE_IDX`/`SCALE_IDX`/`DENSITY_IDX`/`CHMIX_IDX`/`DUTY_BIAS` — **by every write path, not merely the direct one.** The listener's one control for "give me different music" currently discards every parameter they have set, because it was built when Select was the engine's only bad-zone escape; `IP-0007` removed that reason in 2026-07 and nothing re-examined the mechanism. **Boot is unchanged, deliberately and testably.** |

| **Interfaces** | **`init_engine` splits into two entry points, sharing one body.** `init_engine` (boot) keeps its label, its call site in `build_rom.py`'s `main`, and its behaviour byte for byte; it writes the listener-facing values and then **falls through** into a new label — call it the reroll entry — which does everything else and `RET`s. `input_map.py`'s Select handler changes its `CALL` target from `init_engine` to that new label; nothing else about `apply_input` changes and no new routine is called from `engine_tick`. **No new WRAM field, no new ROM table, no new data, no new module.** The one-writer-per-hardware-register discipline `input_map.py`'s own header comment records is preserved exactly. |

| **Rollback Considerations** | **Cleanly revertible, and unusually so for this project.** The change adds no data, no WRAM field and no table; it is an entry-point split plus a `CALL` target. A single-commit `git revert` restores the previous behaviour exactly, with no migration and no persisted state (there is none — MSTR-001 C2).
