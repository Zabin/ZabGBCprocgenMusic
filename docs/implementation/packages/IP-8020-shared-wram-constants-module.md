# IP-8020 — Shared WRAM Constants Module (visuals.py duplication)

| Field | Content |
|---|---|
| **Package ID** | `IP-8020` · `IP-8xx0` refactoring series · **Executor: `08-refactoring`** · cites `BL-0065` |
| **Objective** | `visuals.py` duplicates 11 WRAM-related constants that really live in `music_engine.py` (5 index addresses, 5 preset values, `BAD_ZONE_FLAGS`) as plain ints, deliberately, to keep `visuals.py` from importing `music_engine.py` (an acyclic-import invariant, `GDS-03` §1). That duplication grew from 1 constant (`IP-0006`) to 11 in one later package (`IP-1110`), with nothing preventing further silent drift: a moved address in `music_engine.py` leaves the build green and the visualizer silently reading the wrong byte. Extract the duplicated constants into a new, dependency-free shared module both files import, preserving the acyclic rule (the new module depends on nothing) while removing the single point of silent-drift risk. |
| **Requirements Covered** | None. Purely structural — no `FR`/`NFR` is implemented or affected; the values moved are identical, not corrected (this is not `BL-0022`/any content-fix, it is address relocation only). |
| **Architecture Components** | [`GDS-09` §6](../../architecture/09-interface-specification.md) — the finding this package executes on (duplication risk, "nothing prevents drift"). [`GDS-03` §1](../../architecture/03-architecture.md) — the one-job-per-file/acyclic-import rule this package must preserve, not relax: the new shared module must depend on **nothing** (not on `music_engine.py`, not on `visuals.py`), so both existing files can import it without creating a cycle. [`GDS-07`](../../architecture/07-data-model.md) — the WRAM map these constants describe; unaffected in *value*, only in which file declares them. |
| **Interfaces** | New module, e.g. `wram_constants.py` (repo root, alongside every other single-purpose module — name is this package's own choice at implementation time, not fixed here, provided it is genuinely dependency-free and its name doesn't collide with an existing module). Exports the 5 index addresses (`TEMPO_IDX`/`OCTAVE_IDX`/`SCALE_IDX`/`DENSITY_IDX`/`CHMIX_IDX`), the 5 `PRESET_*` values, and `BAD_ZONE_FLAGS` — exactly the 11 constants `BL-0065` names, no more. `music_engine.py` becomes the module that *defines* these (or itself imports them from the new module, if `music_engine.py` is judged the more natural owner — see Implementation Tasks) and `visuals.py` imports them from the new shared module instead of re-declaring them as local plain ints. |
| **Files to Create/Modify** | **Create**: the new shared constants module (repo root). **Modify**: `music_engine.py` (the 11 constants' canonical definitions move here, or stay here with the shared module importing from `music_engine.py` — see task 1's explicit judgement call) and `visuals.py` (delete the 11 local re-declarations at lines 39-55 — `TEMPO_IDX` through `CHMIX_IDX`, `PRESET_TEMPO_IDX` through `PRESET_CHMIX_IDX`, `BAD_ZONE_FLAGS`; replace with a single import from the new module). **Not touched**: `LY` (`0xFF44`) and `VIS_ENTRY_LY` (`0xC061`) at lines 60/69 of `visuals.py` — confirmed by this package's own scope check (see Risks) that these are **not** instances of the `BL-0065` pattern: `LY` is a hardware register constant with no `music_engine.py` counterpart to duplicate (every module that reads a hardware register declares it independently — `NR52`/`LCDC`/`BCPS`/`BCPD` in this same file are the existing, unremediated precedent, and remediating just one hardware-register constant while leaving the others would be incoherent), and `VIS_ENTRY_LY` is **owned** by `visuals.py` (it is `visuals.py`'s own diagnostic, written only there) with `test_rom.py`'s independent declaration of the same address being a test-harness convention (every WRAM address `test_rom.py` reads is independently declared there, per its own top-of-file block — a much larger, pre-existing, out-of-scope pattern this package does not touch). `input_map.py` — checked, imports `TEMPO_IDX`/`OCTAVE_IDX`/`SCALE_IDX`/`DENSITY_IDX`/`CHMIX_IDX` directly from `music_engine.py` already (`from music_engine import TEMPO_IDX, OCTAVE_IDX, SCALE_IDX, DENSITY_IDX, CHMIX_IDX, _emit_apply_style`) — no duplication there to fix; **input_map.py should switch its import to the new shared module too if the constants' canonical home moves there** (task 2), to avoid two different files importing the same values from two different places. |
| **Implementation Tasks** | (1) **Judgement call, decide before writing code**: should the new module be the constants' new canonical *definition*, with `music_engine.py` importing them back (cleanest single-source-of-truth, but touches `music_engine.py`'s own internal structure more than strictly necessary), or should `music_engine.py` keep defining them with the new module merely *re-exporting* them for `visuals.py` (smaller diff, but leaves two files that could each plausibly be "the" source, which is a milder version of the problem this package exists to fix)? Recommend the former — a genuine single source of truth — but this is `08-refactoring`'s call to make explicitly at execution time, not pre-decided here, and it must be recorded in the Implementation Summary either way. (2) Create the new module with the 11 constants (values copied exactly, not re-derived — this is a *move*, verify byte-for-byte against the current `visuals.py` declarations before deleting them). (3) Update `music_engine.py` per task 1's decision. (4) Update `visuals.py`: delete the 11 local declarations, add one import line from the new module. (5) Update `input_map.py`'s import if task 1 moved canonical ownership. (6) Capture the baseline (ROM SHA-256 + full check-name list) **before** step 2, per `08-refactoring`'s Step 3 — this must happen before any edit, not retroactively. (7) Rebuild, diff the hash — **must be byte-identical**: moving Python-level constant declarations between modules changes nothing about the bytes `gbc_lib.ROM` emits, since these are build-time Python values, not ROM data. (8) Run the full suite; identical check-name set to the baseline. |
| **Tests to Add** | None — same reasoning as `IP-8010`: the equivalence proof (byte-identical ROM, identical check-name set) is the verification. Do not add a test asserting the new module's existence or its values match `music_engine.py`'s — that would test the refactor's own mechanics rather than any shipped behavior, and would need updating every time an unrelated constant is added to either file. |
| **Documentation Updates** | `Claude.md`'s Architecture Overview `visuals.py` line ("read-only consumer of engine state (never writes engine state or PSG registers)") is unaffected in substance but its "one job per file" table may want the new module named, at implementer's discretion — optional, not a Definition-of-Done item, since the table describes *behavioral* responsibility, not every file that exists. `GDS-07`'s WRAM map is unaffected — addresses don't move, only which Python module declares them. `docs/pipeline/backlog.md` is not this package's to write (the manager harvests). |
| **Definition of Done** | The 11 `BL-0065`-named constants have exactly one canonical Python-level definition, imported (not re-declared) by every file that uses them. `visuals.py` no longer contains local re-declarations of any of the 11. ROM is **byte-identical** to the pre-refactor baseline. Full suite passes with the identical check-name set. `LY`/`VIS_ENTRY_LY` are explicitly confirmed untouched and out of scope (see Files to Create/Modify's own reasoning) — this package does not creep into "fix every plain-int constant in `visuals.py`," only the 11 `BL-0065` actually names. |
| **Verification Checklist** | ROM builds, exactly 32768 bytes, valid header (G5). Full `test_rom.py` suite passes (G5). **Equivalence contract: byte-identical ROM** (SHA-256 match) — the default and only acceptable outcome; these are Python-level constant relocations with no ROM-data-layout consequence, so any hash difference is a defect in this package's own execution (e.g. a typo'd value during the move), not a predicted delta to justify. `09-package-verification` independently confirms: (a) the hash match from a clean rebuild, (b) that `visuals.py` genuinely no longer locally declares any of the 11 constants (grep-checkable), (c) that the acyclic-import rule still holds (the new module imports nothing from either `music_engine.py` or `visuals.py`). |
