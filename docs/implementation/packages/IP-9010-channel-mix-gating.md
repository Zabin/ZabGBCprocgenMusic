# IP-9010 — Channel-mix gating (remediation for `BL-0019`)

| Field | Content |
|---|---|
| **Package ID** | `IP-9010` |
| **Objective** | Wire `CHMIX_IDX` to an actual channel-activity-mask table so the Start button's already-correct index-stepping produces an audible, `NR52`-visible effect: only the channels the current mix preset includes should generate/sound; the rest should report inactive in `NR52`, matching `FR-1000`/`FR-1010`'s text and closing `BL-0019`. |
| **Requirements Covered** | `FR-1000` ("...begins generating audio on all channels its channel-mix preset activates..."), `FR-1010` ("...such that `NR52` reports each active channel as currently playing when its channel-mix preset includes it"), `FR-1060` (Start steps `CHMIX_IDX` — already satisfied, unaffected by this package) |
| **Architecture Components** | GDS-03 §3 (`Start` → "Active-channel mix... which of the 4 channels currently contribute"), GDS-07 §1 (`CHMIX_IDX`, `0xC004`, range 0-7) |
| **Interfaces** | New: `CHMIX_MASKS` (or similarly named) — an 8-entry table in `music_engine.py`'s existing preset-data block (alongside `TEMPO_TABLE`/`DENSITY_K`), one 4-bit mask per preset (bit0=pulse A, bit1=pulse B, bit2=wave, bit3=noise — matching `NR52`'s own channel-bit order for a direct, low-risk lookup). Consumed by: `_emit_channel_gen` (pitched channels), `_emit_noise_gen` (noise), and `apply_input`'s existing Start-button handler (unchanged — it already steps the index correctly; this package only adds a *consumer*). |
| **Files to Create/Modify** | `music_engine.py` — add `CHMIX_MASKS` data table; modify `_emit_channel_gen` (`music_engine.py:196-328`, specifically the register-write section around `:296-302`) and `_emit_noise_gen` (`music_engine.py:331-388`, the `NR42`/`NR43`/`NR44` write section around `:359-361`) to check the current channel's mask bit against `CHMIX_IDX`-indexed `CHMIX_MASKS` before writing PSG trigger registers. No changes to `input_map.py` (Start-button stepping is already correct) or `build_rom.py` (no new boot-time init beyond what `init_engine`'s existing `PRESET_CHMIX_IDX` reset-write already does). |
| **Implementation Tasks** | (1) Design `CHMIX_MASKS`' 8 preset values — at minimum preset 0 (`PRESET_CHMIX_IDX`) must be "all 4 channels active" (`0b1111`) to preserve every existing test's boot-time assumption (T2/T3/T6/T7/T9 all assume all channels active at boot); the remaining 7 presets are free to explore useful combinations (GDS-03 §3's own example: "a channel-mix preset using only the two pulse channels" — cite this as one data point, not a mandate for the full table). (2) In `_emit_channel_gen`, before the register-write block, add a check: read `CHMIX_IDX`, look up `CHMIX_MASKS[CHMIX_IDX]`, test the bit for this channel (`pa`=bit0, `pb`=bit1, `wv`=bit2 — extend the existing `CHANNELS` tuple with a bit-index field, matching the existing `octave_delta`/`tempo_mult` per-channel-parameter pattern); if clear, skip the frequency/trigger register writes for this tick (the note-timer/degree/stale bookkeeping should still run, so the channel's internal state stays consistent and it resumes cleanly the moment its mask bit is re-enabled by a later Start press) **and** ensure the channel's DAC/output is actually silenced — the exact mechanism (skip-trigger-only vs. explicit DAC-off write) is a stage-08 implementation decision, but the Definition of Done's `NR52` requirement is not negotiable: an excluded channel must read inactive in `NR52` within one note-cycle of its mask bit clearing, not merely stop retriggering. (3) Same pattern in `_emit_noise_gen` for the noise channel's bit (bit3). (4) Confirm `CHMIX_IDX`'s existing reset-to-preset (`init_engine`, `music_engine.py:509`) needs no change — it already writes `PRESET_CHMIX_IDX`, and this package's task (1) guarantees that preset means "all active." |
| **Tests to Add** | New `test_rom.py` suite (e.g. `T11`): (a) boot with default `CHMIX_IDX=0`, confirm all 4 channels report active in `NR52` (should already pass, given task 1's constraint — a regression guard); (b) step `CHMIX_IDX` via Start to a non-default preset whose mask excludes at least one channel, run enough frames for that channel's current note to finish, confirm `NR52`'s corresponding bit reads inactive while the others remain unaffected; (c) step back to a mask that re-includes the channel, confirm it resumes generating and reporting active. Also revisit T2/T3/T6/T7/T9 (which all implicitly assume `CHMIX_IDX=0`/all-channels-active at boot) — confirm none need updating given task 1's constraint, and note explicitly in the package's own Implementation Summary if any do. |
| **Documentation Updates** | `Claude.md` (remove the two "wired, not yet consumed" notes, describe the actual gating mechanism briefly), `memory.md` (update the `CHMIX_IDX` WRAM quick-ref entry to drop "not yet consumed"), `docs/pipeline/backlog.md` (`BL-0019` → `DONE` once verified). |
| **Definition of Done** | `CHMIX_MASKS` (or equivalent) exists and is consumed by all 4 channels' generation routines; an excluded channel silences (inactive in `NR52`) and a re-included channel resumes, both confirmed by the new test suite; every pre-existing test still passes (regression); ROM still builds to 32768 bytes with a valid header. |
| **Verification Checklist** | ROM builds, exactly 32768 bytes, valid header (G5). Full `test_rom.py` suite passes, including the new suite (G5). `NR52` correctly reflects `CHMIX_IDX`'s current mask for at least one non-default, non-trivial combination, independently re-driven live by `09-package-verification` (not just trusting the new suite's own fixture) — per this project's tunable-parameter verification standard (see `VR-0002`/`VR-0003`/`VR-0004`'s precedent). |
| **Dependencies** | None blocking — builds on `IP-0001`-`IP-0003`'s already-`VERIFIED` `CHANNELS`/`_emit_noise_gen` code; no other in-flight package touches the same lines. |
| **Risks** | ROM-budget: one new 8-byte data table (`CHMIX_MASKS`), negligible against the 32768-byte budget (current build has ample headroom, per GDS-07 §6's own note). Correctness risk: an incorrectly-designed mask table (e.g. a preset that excludes *all* channels) would leave the engine audibly silent — task 1 should sanity-check every preset includes at least one channel. Scope risk: silencing a channel via DAC-off vs. skip-trigger has different corner-case behavior (e.g. does a silenced channel's own bad-zone dissonance contribution still count in `_emit_pairwise_dissonance`, which unconditionally reads all 3 pitched channels' semitones regardless of `NR52` state?) — flagged for stage 08 to resolve explicitly (a reasonable default: dissonance scoring should skip a channel currently excluded by the mix, but this is a real design decision stage 08 must make and document, not silently default one way). |
| **Rollback Considerations** | Fully additive (`CHMIX_MASKS` + gating checks) — reverting is a straightforward revert of the stage-08 commit; no data migration, no WRAM layout change (still uses the existing `CHMIX_IDX` at `0xC004`). |
